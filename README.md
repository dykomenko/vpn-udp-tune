# udp-tune

Настройка UDP-буферов Linux для VPN-сервера (Hysteria2 и другие QUIC-протоколы) с проверкой, что настройки применились.

Нужна, когда `nstat` показывает растущие `UdpRcvbufErrors`: ядро выбрасывает входящие UDP-пакеты, потому что буфер сокета переполняется, и клиенты получают низкую скорость.

## Запуск

```bash
curl -fsSL https://raw.githubusercontent.com/dykomenko/vpn-udp-tune/main/udp-tune.sh -o udp-tune.sh && sudo bash udp-tune.sh
```

Скрипт спрашивает объём ОЗУ и размер буфера на сокет, показывает, что запишет, и просит подтверждение. Настройки сохраняются в `/etc/sysctl.d/99-udp-tuning.conf`, старый файл копируется рядом как `.bak`.

| ОЗУ | Буфер на сокет | Доля ОЗУ под весь UDP |
|---|---|---|
| меньше 8 ГБ | 8 МБ | 15% |
| 8–31 ГБ | 16 МБ | 20% |
| 32–127 ГБ | 32 МБ | 25% |
| 128 ГБ и больше | 64 МБ | 25% |

## Проверка

Повторить проверку, ничего не меняя:

```bash
sudo bash udp-tune.sh --check
```

Проверяет четыре вещи:

1. значения в файле совпадают со значениями в ядре (`OK` / `НЕ СОВПАДАЕТ`);
2. сколько UDP-сокетов по процессам уже с большим буфером, а сколько со старым;
3. память под UDP против лимита `udp_mem`;
4. ошибки приёма UDP за 10 секунд (0–50 норма, тысячи плохо).

Сокеты, открытые до применения настроек, получат новый буфер только после перезапуска их процесса.

## Ошибки UDP в реальном времени

```bash
watch -n1 'nstat -z UdpRcvbufErrors UdpInErrors'
```

`nstat` без `-a` показывает прирост с прошлого вызова, поэтому в `watch` видно число ошибок за секунду.

## Текущее потребление и максимум

Сколько сокетов процесса теряют пакеты (во второй строке должен быть `0`):

```bash
watch -n2 'echo "сокетов rw-core: $(ss -uamnp | grep -c rw-core)"; echo "из них с потерями: $(ss -uamnp | tail -n +2 | paste - - | grep rw-core | grep -vc "d0)")"'
```

Если число больше нуля, показать эти сокеты списком:

```bash
ss -uamnp | tail -n +2 | paste - - | grep rw-core | grep -v 'd0)'
```

Как читать строку `skmem:(r0,rb33554432,...,d0)` одного сокета (`ss -uamnp`):

| Поле | Что значит | Норма |
|---|---|---|
| `r` | сколько байт сейчас в очереди сокета | близко к 0 |
| `rb` | максимум буфера сокета | размер, который вы настроили (33554432 = 32 МБ) |
| `d` | сколько пакетов сокет уже выбросил | 0 |

Остальные поля (`t`, `tb`, `f`, `w`, `o`, `bl`) для этой проблемы не важны.

```bash
watch -n1 "grep UDP: /proc/net/sockstat; sysctl -n net.ipv4.udp_mem"
```

`mem` в `sockstat` это потребление в страницах (4096 байт), последнее число `udp_mem` это жёсткий лимит.
